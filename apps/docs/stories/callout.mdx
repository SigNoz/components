# Callout

A tinted message with a severity: an icon and a description, always visible. A plain `Callout` has
no title and no chevron. Expansion, dismissal and links come from sub-components, so the static one
stays static.

`color`, `size`, `icon` and the children are all required. The callout has no default appearance,
every call site says what it is.

## How to use

```tsx
import { SolidInfoCircle } from '@signozhq/icons';
import { Callout } from '@signozhq/ui';

export default function MyComponent() {
	return (
		<Callout color="primary" size="md" icon={<SolidInfoCircle />}>
			Instrumentation is the code that produces telemetry.
		</Callout>
	);
}
```

## Colors

`color` is one of `primary`, `secondary`, `success`, `danger`, `warning`, `info`, `archive` and
`highlight-danger`. It sets the tint and the live region role.

Every color has its own tint. `secondary` is the neutral surface, and `info`, `archive` and
`highlight-danger` take the hues Badge uses for the same names.

```tsx
<Callout color="danger" size="sm" icon={<SolidXCircle />}>
	The request failed. Try again in a moment.
</Callout>
```

## Sizes

`size` is `sm` or `md`. It sets the type scale and the icon size, 12 at `sm` and 16 at `md`. Both
sizes have the same padding.

## Icon

The icon is required, because it carries the severity for users who cannot tell the tints apart. It
is hidden from assistive tech. The callout sets its size, and the one passed on the element is
ignored. It takes the color of the callout, and a color set on the icon element wins.

## Empty content

`Callout` and `Callout.Closeable` render nothing while the children are empty, since a tinted box
with only an icon carries no message. `null`, `false` and `''` all return no element.

```tsx
// renders nothing while `error` is undefined
<Callout color="danger" size="sm" icon={<SolidXCircle />}>
	{error}
</Callout>
```

## Overflow

Without `width` the callout fills its parent, and `maxWidth` caps it at the width of the parent. It
has no outer margin, so the parent owns the spacing around it.

The height grows with the content. When the parent has no vertical space left, `maxHeight` stops
the growth and the description scrolls, while the icon and the title row stay pinned. Text wraps
first, so a long word never forces a horizontal scroll.

```tsx
<Callout color="primary" size="sm" icon={<SolidInfoCircle />} maxWidth={742}>
	A note that should not grow wider than the form it sits in.
</Callout>
```

## Keyboard

The callout itself is not focusable. The title row, the close button and the links take focus, in the
order they show on screen. `Esc` does nothing, a callout is not an overlay.

The description is never made focusable. When it scrolls, Chromium and Firefox let a keyboard user
focus it and scroll with the arrow keys on their own (Chromium only while it holds no link). Safari
does not, so avoid a `height` or `maxHeight` that makes a long description scroll.

## Callout.Expandable

A callout whose description the user can hide. It is the only callout with a `title`, since the
title row and the chevron are what stay visible when collapsed. `defaultExpanded` is required, and
the state is uncontrolled.

```tsx
<Callout.Expandable
	color="primary"
	size="md"
	icon={<SolidInfoCircle />}
	title="What is instrumentation?"
	defaultExpanded
>
	Instrumentation is the code that produces telemetry.
</Callout.Expandable>
```

The whole title row is one button, so a click on the title or on the chevron toggles. A click on the
description does nothing, since it holds links and text to select. The row is named by the title and
points at the description.

The title is a single line. A long one ends in an ellipsis, and a tooltip shows the whole of it
while it is cut, on hover and on keyboard focus. Pass a string, since the ellipsis and the tooltip only work with a string.

It never hides: an empty title shows `<No title>` and an empty description shows `<No description>`,
so a broken message stays visible. Both are exported, as `CALLOUT_EMPTY_TITLE` and
`CALLOUT_EMPTY_DESCRIPTION`.

## Callout.Closeable

A callout with a close button on the right edge. It keeps no state: it renders nothing while `closed`
is `true`, and the close button calls `onClose`, where you set `closed`. Setting `closed` back to
`false` shows it again, for example when a new message arrives after a dismissal.

When the close button had focus and `onClose` closes the callout, focus moves to the next tabbable
element after the callout, or to the last one before it when nothing follows. Focus `onClose` moves
somewhere else stays there. A `closed` set later, after an `await`, leaves focus on the page body.

The close button is named `Dismiss`. Give `closeAriaLabel` when several closeable callouts sit on one
page, so a screen reader user can tell their buttons apart, and to translate it.

```tsx
const [closed, setClosed] = useState(false);

<Callout.Closeable
	color="warning"
	size="md"
	icon={<SolidAlertTriangle />}
	closed={closed}
	onClose={() => setClosed(true)}
	closeAriaLabel="Dismiss the trial notice"
>
	Your trial ends in 3 days.
</Callout.Closeable>;
```

## Callout.CloseablePersisted

A closeable callout that stays hidden after a reload. It owns its state, so it takes no `closed`, and
`onClose` is only for side effects. It saves the dismissal in `localStorage` under `storageKey` as
`"true"`, the value the app already writes, so a hand-rolled dismissal migrates without showing the
callout again. Closing one hides every other callout with the same `storageKey`, in this tab and in
the others.

```tsx
<Callout.CloseablePersisted
	storageKey="license-callout-dismissed"
	color="primary"
	size="md"
	icon={<SolidInfoCircle />}
>
	Add a license key to unlock all features.
</Callout.CloseablePersisted>
```

None of the sub-components is both expandable and closeable.

## Callout.Link

A link for use inside the children. It draws in the link color of the callout around it and inherits
its type. It has no `className` or `style`.

```tsx
<Callout color="primary" size="md" icon={<SolidInfoCircle />}>
	Read the{' '}
	<Callout.Link href="https://signoz.io/docs" target="_blank">
		docs
	</Callout.Link>
	.
</Callout>
```

Pass `render` for a router link. The callout imports no router, so the click is a client-side
navigation and a modified click still opens a new tab. With a `_blank` target, `noopener` and
`noreferrer` join the `rel` of the `render` element, which keeps its other values. Its own `ref`
and `className` are kept too.

```tsx
<Callout.Link render={<Link to="/alerts" />}>alerts</Callout.Link>
```

A link with neither `href` nor a destination on the `render` element renders plain text and warns on
the console.

## Asserting on it

`testId` becomes `data-testid` on the root, and it names everything under it:

| Element          | `data-testid`                 |
| ---------------- | ----------------------------- |
| icon             | `` `${testId}-icon` ``        |
| title            | `` `${testId}-title` ``       |
| description      | `` `${testId}-description` `` |
| title row button | `` `${testId}-toggle` ``      |
| close button     | `` `${testId}-close` ``       |

The title row button renders only on `Callout.Expandable`, and the close button only on
`Callout.Closeable` and `Callout.CloseablePersisted`. `Callout.Link` takes a `testId` of its own.

The root carries `data-color` and `data-size`, and `data-expanded` while expanded.

Otherwise use the `data-slot` attributes, never the hashed class names.
