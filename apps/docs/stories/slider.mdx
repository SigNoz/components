# Slider

Picks one number from a continuous scale, rendered through Base UI's `Slider`. It is for a setting
with a known range (fill opacity in the panel editor), and for an estimate where the exact number
does not matter (the onboarding scale questions). `Slider.Range` picks a lower and an upper bound
(the duration quick filter).

## How to use

The slider has no visible label. Name it with `aria-labelledby`, pointing at the label next to it,
or with `aria-label`. A `<label htmlFor>` does not work, since the input id is internal.

```tsx
import { Slider } from '@signozhq/ui';

export default function FillOpacity({ opacity, setOpacity }) {
	return (
		<>
			<Typography.Text id="opacity-label">Fill opacity</Typography.Text>
			<Slider
				color="primary"
				min={0}
				max={1}
				step={0.01}
				value={opacity}
				onChange={setOpacity}
				aria-labelledby="opacity-label"
			/>
		</>
	);
}
```

<Primary />

`color` is required, with no default. It takes the same hues as `Badge`, and paints the fill, the
thumb border and the mark dots inside the fill. The track and the other dots are tints of it.

`onChange` is called on every change: while the thumb drags, on a click on the track or a mark, and
on each key press. `onAfterChange` is called once when a change ends: on pointer release, on each
key press, and on a click on a mark. Use it for work that should not run on every pixel of a drag,
such as applying a filter.

## Range

`Slider.Range` takes every prop of `Slider`. The value and its callbacks hold a pair, the lower bound
first, so no call site casts the value it receives.

```tsx
<Slider.Range
	color="primary"
	min={0}
	max={100000}
	value={duration}
	onChange={setDuration}
	onAfterChange={applyDurationFilter}
	tooltip
	formatValue={(value) => `${value} ms`}
	aria-label="Duration"
/>
```

The fill runs between the two thumbs. A click on the track moves the closest thumb, and when both
hold the same value, a click or a drag moves the thumb on the side it goes to. A thumb stops
when it reaches the other one, and the two can hold the same value, so a filter can select one
exact value. A drag on one thumb never changes the value of the other.

## Value tooltip

`tooltip` shows the value of each thumb above it. It opens on hover, on press and on keyboard focus,
and stays open while the thumb drags, even when the pointer leaves the thumb.

`formatValue` formats the value for the tooltip and for `aria-valuetext`, so a screen reader reads
the same text the tooltip shows. Without it, both use the raw number.

Do not wrap the slider in a `Tooltip`. Use `tooltip` and `formatValue`.

## Marks

`marks` are labels under the track, keyed by the value they point at. Each mark also draws a dot on
the track. A click on a label or its dot moves the closest thumb to the mark value, and calls
`onChange` and `onAfterChange` once each. When the two thumbs of a range hold the same value, the
thumb on the side of the mark moves.

The label row sits inside the slider, so the slider grows taller and the next element moves down
with no margin. A label at `min` aligns with the start of the track, one at `max` with its end, and
every other one is centred on its value. A mark outside `min` and `max` is not rendered.

Each label has the room up to halfway to the mark on each side, or up to the end of the slider when
there is no mark on that side, so two labels never cover each other. A centred label takes the same
room on both sides of its value. `textOverflow` says what a longer label does:

| `textOverflow`       | a label longer than its room                                    |
| -------------------- | --------------------------------------------------------------- |
| `ellipsis` (default) | truncates, and shows in full in a tooltip under it on hover     |
| `wrap`               | breaks into lines, and the label row grows to the tallest label |

A disabled or read-only reason stacks above the label in the same tooltip.

A slider that stands for a log scale runs from 0 to 100. Key the marks by the slider value, and
compute the label in `formatValue` from the value it receives:

```tsx
<Slider
	color="primary"
	value={position}
	onChange={setPosition}
	marks={{ 0: '1 GB', 25: '10 GB', 50: '100 GB', 75: '1 TB', 100: '10 TB' }}
	tooltip
	formatValue={(position) => formatVolume(10 ** (position / 25))}
	aria-labelledby="logs-volume-label"
/>
```

Marks are not tab stops, and the label row is hidden from screen readers. The arrows, `Home` and
`End` already reach every value.

## Keys

Each thumb is one tab stop. The arrows move one `step`. `PageUp`, `PageDown` and `Shift` with an arrow
move one large step: 10% of `max - min`, rounded to a multiple of `step`, and at least one `step`.
`Home` and `End` move to `min` and `max`, or to the other thumb of a range.

## Value out of the scale

A `value` that is not a finite number renders the thumb at `min`. A value below `min` or above `max`
renders the thumb at the nearest end, and the tooltip and `aria-valuetext` show the value of the
thumb. The slider never calls `onChange` to correct a value, so a duration typed above `max` in the
input next to the slider keeps its value.

## Forms

Each thumb input carries `name` and `form`, so the slider submits with its form like a native range
input. `Slider.Range` submits two values under the same `name`, the lower bound first. `required` is
accepted so a form can pass the same field props to every control, and has no effect: a slider always
holds a value.

## Layout

The slider fills the width of its parent and has no margin. The track runs from edge to edge, and a
thumb at `min` or `max` stays inside it, so the parent needs no margin or padding to make room.

The slider is never narrower than two thumbs. In a narrower parent it paints outside the parent.

A row that prints the value next to the slider owns that layout:

```tsx
<div className="config-row">
	<Typography.Text id="opacity-label">Fill opacity</Typography.Text>
	<div className="config-slider">
		<Slider color="primary" value={opacity} onChange={setOpacity} aria-labelledby="opacity-label" />
	</div>
	<Typography.Text>{opacity.toFixed(2)}</Typography.Text>
</div>
```

```css
.config-slider {
	flex: 1;
	min-width: 0;
}
```

## Asserting on it

`testId` becomes `data-testid` on the root, and it names everything under it:

| Element    | `data-testid`                    |
| ---------- | -------------------------------- |
| track      | `` `${testId}-track` ``          |
| fill       | `` `${testId}-indicator` ``      |
| thumb      | `` `${testId}-thumb-${index}` `` |
| mark label | `` `${testId}-mark-${value}` ``  |

`index` is `0` on `Slider`. On `Slider.Range` it is `0` for the lower bound and `1` for the upper
one. A mark label renders only with `marks`, and carries `data-truncated` while it is cut.

The root carries `data-color` and `data-text-overflow`, and `data-disabled`, `data-readonly`,
`data-dragging` and `data-range` while they apply.

Otherwise use the `data-slot` attributes, never the hashed class names.
