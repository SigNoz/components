# Popover

A floating panel hung off a trigger, rendered through Base UI's Popover. It opens on a press, and
optionally on hover. The popup is a `role="dialog"`: focus moves into it, nothing is trapped, and
Escape closes it.

A label that only describes something is a tooltip. Rows of actions are a dropdown. A popover is
the panel that is neither: a form, a picker, a typeahead, a hover card with links in it.

## How to use

`children`, `side` and `align` are required, and so is `trigger` unless a `handle` is passed.
There are no subcomponents to compose: the popover owns its own markup. `children` is the popup.
`trigger` is the element it hangs off.

```tsx
import { Button, Popover } from '@signozhq/ui';

export default function MarkdownHelp() {
	return (
		<Popover
			nativeButton
			side="bottom"
			align="start"
			trigger={<Button variant="ghost" aria-label="Markdown help" />}
			aria-label="Markdown help"
		>
			<MarkdownCheatsheet />
		</Popover>
	);
}
```

The shell has no padding. The content owns all of it, edge to edge, which is what lets a divider
or a search row run full-bleed.

`nativeButton` says whether `trigger` renders a native `<button>`. It is required alongside a
trigger, since a default of `true` is silently wrong for anything that is not a button: set it to
`false` for a badge, a link or an input. A popover shown from a handle alone has no trigger to
describe, so passing it there is a type error rather than a no-op.

## Opening and closing

The trigger opens it on a press, Enter or Space. It closes on Escape, on an outside press, and
when focus leaves it. `onOpenChange` reports every change, and `eventDetails.reason` says why.
`eventDetails.cancel()` vetoes the change.

With `openOnHover` it also opens while the pointer rests on the trigger, after `delay`. The popup
stays interactive, so the pointer can travel into it to read, select or follow a link, which is
the one thing a Tooltip cannot do. The trigger still opens it on a press, which is the route a
keyboard takes.

The popover owns its open state. Nothing starts open on the first render, and there is no `open`
prop: a surface the application drives uses a `handle`.

## Showing it from application state

Some popups cannot come from a trigger press at all. A drilldown menu belongs at the point of a
chart click, where there is no element to hang a trigger off. A hover card over a waterfall belongs
next to whichever row the pointer entered, and declaring one popover per row would mean hundreds of
them. A form inside a popup has to close itself once its save succeeds, which the popover cannot
know.

`usePopoverHandle()` covers all three. `showAt(target, payload)` shows the popup against an
element, a `DOMRect` or a `{ x, y }` point, and `close()` dismisses it whichever way it opened.

```tsx
import { Popover, usePopoverHandle } from '@signozhq/ui';

export default function Waterfall({ spans }) {
	const card = usePopoverHandle<Span>();

	return (
		<>
			{spans.map((span) => (
				<Row key={span.id} onMouseEnter={(event) => card.showAt(event.currentTarget, span)} />
			))}
			<Popover side="right" align="start" handle={card} initialFocus={false}>
				{(span) => <SpanSummary span={span} />}
			</Popover>
		</>
	);
}
```

Pass `children` as a function to receive the payload of the most recent `showAt`. One declared
popover then serves every row, moving and swapping its content instead of mounting a popup each.

A handle and a trigger can coexist: the handle owns the open state, so a press and a `showAt`
cannot disagree, and `close()` works whichever of them opened it.

## Placement

`side` and `align` are required. The gap is a fixed 4px and the alignment offset is fixed at 0.
The popup flips to the opposite side and shifts along its alignment axis to stay in view.

`width`, `maxWidth` and `maxHeight` size the shell. Past `maxHeight`, or the room the viewport
leaves, the content scrolls.

`anchor` points the popup at something that is not the trigger, such as the input row of a
typeahead, for a popover that still has a trigger. A handle's `showAt` target wins over it while
the handle is showing. `initialFocus={false}` leaves the caret where it was.

## Inside a dialog

Anywhere else the popup goes to the body. Inside a `Dialog` or `Drawer` it portals into the panel,
where the focus trap lets the keyboard reach the content.

## Limitations

**The trigger cannot be a `Tooltip`.** A control that both names itself on hover and opens a popup
on a press is a common shape, and wrapping the trigger does not give you it:

```tsx
// Does not open. The press never reaches the button.
<Popover
	nativeButton
	side="bottom"
	align="end"
	trigger={
		<Tooltip title="Download">
			<button type="button">Download</button>
		</Tooltip>
	}
>
	<ExportFormats />
</Popover>
```

A Tooltip that is not itself inside another tooltip trigger routes every prop it does not
recognise to its own popup, so the press handlers the popover merges into `trigger` land on the
tooltip rather than on the button underneath. The tooltip still works; the popover never opens.

Drive the popover from a handle instead, and leave the button to the tooltip:

```tsx
const menu = usePopoverHandle();

<Tooltip title="Download">
	<button type="button" onClick={(event) => menu.showAt(event.currentTarget)}>
		Download
	</button>
</Tooltip>
<Popover side="bottom" align="end" handle={menu} aria-label="Export">
	<ExportFormats />
</Popover>;
```

The popover has no trigger of its own in that shape, so `aria-haspopup` and `aria-expanded` belong
on the button. `popover.tooltip-trigger.test.tsx` pins the behaviour so the day it is fixed is
visible.

**There is no controlled `open` prop.** The popover owns its open state and reports it through
`onOpenChange`. Application-driven visibility goes through a `handle`.

## What this is not

- A short label that only describes the thing under the pointer is a `Tooltip`. Content the
  pointer has to reach, such as a link, a copy button or a scrollable body, is a hover popover.
- A menu of rows that closes when one is picked is a `Dropdown`.

## Asserting on it

`testId` is `data-testid` on the trigger, and the popup is `` `${testId}-popup` ``. The popup
renders only while open.

`ForceOpenProvider`, from `@signozhq/ui/testing`, holds every popover under it open. Stories and
screenshots use it. Call sites do not.

```tsx
import { ForceOpenProvider } from '@signozhq/ui/testing';

<ForceOpenProvider>
	<Popover nativeButton side="bottom" align="start" trigger={<Button>Open</Button>}>
		<p>Held open for the screenshot.</p>
	</Popover>
</ForceOpenProvider>;
```
