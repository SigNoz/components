# Popover

A floating panel hung off a trigger, rendered through Base UI's Popover. It opens on a click. The
popup is a `role="dialog"`: focus moves into it, nothing is trapped, and Escape closes it.

A surface that opens on hover is a tooltip. A menu at the pointer is a context menu. Rows of
actions are a dropdown. A popover is the panel that is none of those: a form, a picker, a
typeahead.

## How to use

`trigger`, `children`, `side`, `align` and `nativeButton` are required. There are no
subcomponents to compose: the popover owns its own markup. `children` is the popup. `trigger` is
the element it hangs off.

```tsx
import { Button, Popover } from '@signozhq/ui';

export default function SaveView({ open, onOpenChange }) {
	return (
		<Popover
			nativeButton
			side="bottom"
			align="end"
			trigger={<Button variant="outlined">Save view</Button>}
			open={open}
			onOpenChange={onOpenChange}
			aria-label="Save view"
		>
			<SaveViewForm onDone={() => onOpenChange(false)} />
		</Popover>
	);
}
```

The shell has no padding. The content owns all of it, edge to edge, which is what lets a divider
or a search row run full-bleed.

`nativeButton` says whether `trigger` renders a native `<button>`. It is required: a default of
`true` is silently wrong for anything that is not a button. Set it to `false` for a badge, a link,
or an input.

## Opening and closing

The trigger opens it on a press, Enter or Space. It closes on Escape, on an outside press, and
when focus leaves it. `onOpenChange` reports every change, and `eventDetails.reason` says why.
`eventDetails.cancel()` vetoes the change.

The popover owns its open state. Controlled `open` is for what the popup cannot know by itself: a
form that closes only when its save succeeds, or a list that keeps one popover open at a time.
Nothing starts open on the first render.

## Placement

`side` and `align` are required. The gap is a fixed 4px and the alignment offset is fixed at 0.
The popup flips to the opposite side and shifts along its alignment axis to stay in view.

`width`, `maxWidth` and `maxHeight` size the shell. Past `maxHeight`, or the room the viewport
leaves, the content scrolls.

`anchor` points the popup at something that is not the trigger, such as the input row of a
typeahead. The trigger is still required. `initialFocus={false}` leaves the caret where it was.

## Inside a dialog

Anywhere else the popup goes to the body. Inside a `Dialog` or `Drawer` it portals into the panel,
where the focus trap lets the keyboard reach the content.

## What this is not

- Hover content, including a key-value description, is a `Tooltip`.
- A menu of rows that closes when one is picked is a `Dropdown`.
- A menu that opens at the pointer, with no trigger element, is a context menu.

## Asserting on it

`testId` is `data-testid` on the trigger, and the popup is `` `${testId}-popup` ``. The popup
renders only while open.

`ForceOpenProvider`, from `@signozhq/ui/testing`, holds every popover under it open. Stories and
screenshots use it. Call sites do not.

```tsx
import { ForceOpenProvider } from '@signozhq/ui/testing';

<ForceOpenProvider>
	<Popover nativeButton side="bottom" align="start" trigger={<Button>Open</Button>}>
		<p>Held open for the screenshot.</p>
	</Popover>
</ForceOpenProvider>;
```
