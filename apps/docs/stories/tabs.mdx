# Tabs

Renders a tab bar and its panels from an `items` array, with primary and secondary variants,
prefix/suffix icons, disabled tabs with a required tooltip reason, and optional tab bar extra
content. A tab can also navigate instead of holding a panel, see
[Tabs that navigate](#tabs-that-navigate).

## How to use

```tsx
import { Tabs } from '@signozhq/ui';

const items = [
	{ key: 'overview', label: 'Overview', children: 'Overview content' },
	{ key: 'analytics', label: 'Analytics', children: 'Analytics content' },
	{ key: 'settings', label: 'Settings', children: 'Settings content' },
];

export default function MyComponent() {
	return (
		<Tabs
			variant="primary"
			orientation="horizontal"
			alignment="left"
			items={items}
			defaultValue="overview"
		/>
	);
}
```

## Variants

Switch between `primary` (default) and `secondary` styles with the `variant` prop:

```tsx
// Primary — underline indicator with hover slider
<Tabs variant="primary" orientation="horizontal" alignment="left" items={items} defaultValue="overview" />

// Secondary — pill-style tabs with a bottom border
<Tabs variant="secondary" orientation="horizontal" alignment="left" items={items} defaultValue="overview" />
```

## With icons

Add `prefixIcon` or `suffixIcon` to tab items to display icons alongside the label:

```tsx
import { Settings, History } from '@signozhq/icons';

<Tabs
	variant="primary"
	orientation="horizontal"
	alignment="left"
	defaultValue="settings"
	items={[
		{
			key: 'settings',
			label: 'Settings',
			prefixIcon: <Settings style={{ width: '1rem', height: '1rem' }} />,
			children: 'Settings content',
		},
		{
			key: 'history',
			label: 'History',
			suffixIcon: <History style={{ width: '1rem', height: '1rem' }} />,
			children: 'History content',
		},
	]}
/>;
```

## Disabled tabs

A disabled tab must always say why: `disabledTooltip` is required whenever `disabled` is set, and
shows on hover or keyboard focus.

```tsx
<Tabs
	variant="primary"
	orientation="horizontal"
	alignment="left"
	defaultValue="active"
	items={[
		{ key: 'active', label: 'Active', children: 'Active content' },
		{
			key: 'locked',
			label: 'Issues',
			disabled: true,
			disabledTooltip: 'Feature is under maintenance',
			children: 'Issues content',
		},
	]}
/>
```

## Tab bar extra content

Render additional content to the left or right of the tab list with `tabBarLeftContent` and
`tabBarRightContent`:

```tsx
import { Button, ButtonVariant, ButtonSize, ButtonColor } from '@signozhq/ui';
import { Plus } from '@signozhq/icons';

<Tabs
	variant="primary"
	orientation="horizontal"
	alignment="left"
	items={items}
	defaultValue="overview"
	tabBarRightContent={
		<Button
			variant={ButtonVariant.Outlined}
			size={ButtonSize.SM}
			color={ButtonColor.Secondary}
			prefix={<Plus style={{ width: '1rem', height: '1rem' }} />}
		>
			Add view
		</Button>
	}
/>;
```

## Alignment

Control how the tab list positions itself within its container using the `alignment` prop (`left`,
`center`, `right`).

## No content padding

`noTabContentPadding` removes the padding around the active panel, for a panel that manages its own
spacing:

```tsx
<Tabs variant="primary" orientation="horizontal" alignment="left" items={items} noTabContentPadding />
```

## Tabs that navigate

An item that carries `render` instead of `children` renders as whatever you hand over, a router
`Link` in practice, and keeps `role="tab"`, the arrow keys and every `data-*` the bar stamps. The
tab is then a real anchor, so middle click, "open in new tab" and the URL in the status bar work,
which no `onChange` handler can give you.

Those items have no panel of their own. The panel is the bar's `children`, rendered for whichever
tab is active:

```tsx
import { Link, Outlet, useLocation } from 'react-router-dom';
import { Tabs } from '@signozhq/ui';

function ServiceTabs() {
	const { pathname } = useLocation();

	return (
		<Tabs
			variant="primary"
			orientation="horizontal"
			alignment="left"
			value={pathname.split('/').at(-1)}
			items={[
				{ key: 'overview', label: 'Overview', render: <Link to="overview" /> },
				{ key: 'logs', label: 'Logs', render: <Link to="logs" /> },
			]}
		>
			<Outlet />
		</Tabs>
	);
}
```

Leave the `children` out when the `Outlet` already lives elsewhere in the tree, and the bar renders
tabs alone.

Such a bar is controlled: `value` comes from the router, so back and forward move it too.
`defaultValue` is refused, and so is passing `children` alongside items that bring their own.
`onChange` still fires on click, which makes it useful for analytics, but it is not how the
navigation happens.

A `disabled` item ignores `render` and falls back to the plain `<button>`: an anchor is still
followed by a middle click and still offers "open in new tab", so rendering one would be a lock
anybody can walk around.

## Controlled state

Pass `value` and `onChange` to drive the active tab from external state:

```tsx
import { useState } from 'react';
import { Tabs } from '@signozhq/ui';

function MyComponent() {
	const [active, setActive] = useState('overview');

	return (
		<Tabs
			variant="primary"
			orientation="horizontal"
			alignment="left"
			items={items}
			value={active}
			onChange={setActive}
		/>
	);
}
```
