# Calendar

A month grid that draws and navigates itself, with no calendar library underneath. It selects a
single day, several days or a range, takes `disabled` matchers, writes every name and label in the
`locale` you give it as a BCP 47 string, and works from the keyboard. An app that holds its dates
in dayjs, or any other type, builds a typed calendar with `createCalendar(adapter)`.

Use it when the grid itself belongs on the page, such as a panel that always shows the month. To
pick a date from a field in a form or a toolbar, put it in a `Popover` behind an input.

## How to use

`mode` is the one required prop. The rest has a default:

- `showOutsideDays` is `true`, so the grid keeps six even rows.
- `captionLayout` is `'label'`.
- `locale` is `'en-US'`.

```tsx
import { Calendar } from '@signozhq/ui';
import { useState } from 'react';

export default function ReportStart() {
	const [date, setDate] = useState<Date>();

	return <Calendar mode="single" selected={date} onSelect={setDate} />;
}
```

## Selection

`mode` decides what `selected` holds and what `onSelect` receives first. `onSelect` is called with
`(selected, triggerDate, modifiers, event)`: the new selection, the day that was clicked, that
day's flags as a `Record<string, boolean>` (`today`, `outside`, `disabled`, `hidden`, `focused`,
`selected`, `range_start`, `range_middle` and `range_end`) and the click event.

| `mode`     | `selected` and `onSelect` value |
| ---------- | ------------------------------- |
| `single`   | `Date \| undefined`             |
| `multiple` | `Date[] \| undefined`           |
| `range`    | `DateRange \| undefined`        |

```tsx
import { Calendar, type DateRange } from '@signozhq/ui';
import { useState } from 'react';

export default function ReportWindow() {
	const [range, setRange] = useState<DateRange | undefined>();

	return <Calendar mode="range" selected={range} onSelect={setRange} numberOfMonths={2} />;
}
```

- `required` stops a click on the selected day from clearing it, so `onSelect` never receives
  `undefined`.

A day inside a range carries `data-range-start`, `data-range-middle` or `data-range-end` rather
than `data-selected-single`, so the three positions are painted apart.

A range reads as one band. Its days paint across the gaps between them, the two ends are rounded
on their outer side only, and the band stops at the edge of a week row. With `numberOfMonths` above
one, an outside day whose own month is also displayed is not painted as part of the range, because
that month already shows it. Its attributes still say where it falls in the range. The first
month's leading and the last month's trailing outside days have no other copy, so they paint.

## Caption and navigation

The month arrows sit over the caption row, one cell wide each.

- `captionLayout="dropdown"` swaps the caption for a month and a year dropdown. Use
  `dropdown-months` or `dropdown-years` to swap only one of them. Bound the years with
  `startMonth` and `endMonth`.
- At the edge of `startMonth` or `endMonth` the arrow stays in place with `aria-disabled`, so the
  caption does not shift.
- `hideNavigation` drops the arrows.
- `numberOfMonths` lays out more than one month side by side.
- `fixedWeeks` always draws six weeks, and `showWeekNumber` adds a column with the week number.

```tsx
<Calendar
	mode="single"
	captionLayout="dropdown"
	startMonth={new Date(2024, 0)}
	endMonth={new Date(2026, 11)}
/>
```

The calendar owns the displayed month unless you pass `month`. Use `defaultMonth` to open on a
month and let the user move from there. Use `month` and `onMonthChange` when something else, such
as a preset button, has to move it.

## Days that cannot be picked

`disabled` takes `true`, a date, an array of dates, `{ from, to }`, `{ before }`, `{ after }`,
`{ before, after }`, `{ dayOfWeek }`, a function that receives a date, or an array mixing any of
those.

```tsx
<Calendar mode="single" selected={date} onSelect={setDate} disabled={[{ dayOfWeek: [0, 6] }]} />
```

A disabled day is a natively disabled button, except the focused one, which uses `aria-disabled`
so the day stays reachable by keyboard.

## Footer

`footer` renders under the grid in a polite live region, so a screen reader reads it out when it
changes. It is set at the size and in the colour of the weekday labels.

```tsx
<Calendar
	mode="single"
	selected={date}
	onSelect={setDate}
	footer="Pick the day the report starts on."
/>
```

## Keyboard and focus

The grid has one tab stop, the day that has focus, else the selected day, else today, else the
first day that can take focus.

| Key                              | Does                                             |
| -------------------------------- | ------------------------------------------------ |
| `ArrowLeft`, `ArrowRight`        | moves focus to the previous or next day          |
| `ArrowUp`, `ArrowDown`           | moves focus to the previous or next week         |
| `Home`, `End`                    | moves focus to the first or last day of the week |
| `PageUp`, `PageDown`             | moves focus to the previous or next month        |
| `Shift+PageUp`, `Shift+PageDown` | moves focus to the previous or next year         |
| `Enter`, `Space`                 | selects the focused day                          |

Arrow keys step over days that are disabled. When focus leaves the months on screen, the calendar
moves to the month it landed in, and it stops at `startMonth` and `endMonth`.

## Locale

`locale` is a BCP 47 tag, `en-US` by default. The caption, the weekday names, the month names in
the dropdown and every accessible label are written through `Intl.DateTimeFormat` for that tag.
For `en-*` the labels read as English with ordinals, such as
`Today, Monday, September 7th, 2026, selected`. Any other tag uses its own `Intl` names.

```tsx
<Calendar mode="single" locale="pt-BR" selected={date} onSelect={setDate} />
```

Set `weekStartsOn` to start the week on another day, `0` being Sunday. `data-day` is always
`YYYY-MM-DD` in Latin digits, whatever the locale.

## Date libraries

`Calendar` works on native `Date`. `createCalendar(adapter)` returns a calendar of the same props
whose dates are the type your app holds: `selected`, `today`, `month`, `defaultMonth`,
`startMonth`, `endMonth`, the dates in `disabled`, and the dates `onSelect` and `onMonthChange`
receive.

The adapter has two functions. `toDate` returns the wall clock of a value as a `Date` whose local
fields (year, month, day, hours, minutes, seconds) hold it, and `fromDate` does the reverse. The
calendar passes `undefined` as the time zone, so the adapter works in the browser's zone.

```tsx
import { createCalendar, type DateAdapter } from '@signozhq/ui';
import dayjs, { type Dayjs } from 'dayjs';
import { useState } from 'react';

const dayjsAdapter: DateAdapter<Dayjs> = {
	toDate: (value) =>
		new Date(
			value.year(),
			value.month(),
			value.date(),
			value.hour(),
			value.minute(),
			value.second(),
		),
	fromDate: (date) => dayjs(date),
};

const DayjsCalendar = createCalendar(dayjsAdapter);

export default function ReportStart() {
	const [date, setDate] = useState<Dayjs>();

	return <DayjsCalendar mode="single" selected={date} onSelect={setDate} />;
}
```

Call `createCalendar` once, at module level. A call inside a component builds a new component on
every render and remounts the grid.

## The ref

The ref lands on the root `<div>`.

## Asserting on it

`testId` lands on the root, and every part below derives its own from it, so one prop names the
whole calendar.

```tsx
<Calendar mode="single" testId="report-start" />;

screen.getByTestId('report-start-nav-next');
screen.getByTestId('report-start-button-11-06-2025');
```

| Element           | `data-testid`                                                 |
| ----------------- | ------------------------------------------------------------- |
| root              | `` `${testId}` ``                                             |
| month arrows      | `` `${testId}-nav-previous` ``, `` `${testId}-nav-next` ``    |
| caption dropdowns | `` `${stem}-dropdown-month` ``, `` `${stem}-dropdown-year` `` |
| week number       | `` `${stem}-week-number-${week}` ``                           |
| date cell         | `` `${stem}-button-${DD-MM-YYYY}` ``                          |

`stem` is `testId` while one month is displayed. The calendar renders a caption, a week number and
a day button per displayed month, so with `numberOfMonths` above one the stem becomes
`` `${testId}-month-${n}` ``, counting the months from one as they are laid out.

```tsx
<Calendar mode="range" numberOfMonths={2} testId="report-start" />;

screen.getByTestId('report-start-month-2-button-01-07-2025');
```

Pass no `testId` and no part carries one. Otherwise use the data attributes below, never the hashed
class names.

| Root attribute | Value          |
| -------------- | -------------- |
| `data-slot`    | `"calendar"`   |
| `data-mode`    | mirrors `mode` |

| `data-slot`                 | Rendered                                                         |
| --------------------------- | ---------------------------------------------------------------- |
| `calendar-month`            | one per displayed month, the caption and the grid together       |
| `calendar-button`           | every month arrow and every date cell, `data-variant` says which |
| `calendar-day-button-label` | inside each date cell, holds the day number                      |
| `calendar-week-number`      | only while `showWeekNumber` is set                               |

| Date cell attribute                                       | Set when                                                                |
| --------------------------------------------------------- | ----------------------------------------------------------------------- |
| `data-day`                                                | always, the day as `YYYY-MM-DD` in Latin digits (see [Locale](#locale)) |
| `data-today`                                              | the day is today                                                        |
| `data-outside`                                            | the day belongs to a neighbouring month                                 |
| `data-duplicate`                                          | an outside day whose own month is displayed too                         |
| `data-selected-single`                                    | selected, and not part of a range                                       |
| `data-range-start`, `data-range-middle`, `data-range-end` | the day's position in a range                                           |

The `<td>` around the button adds `data-disabled`, `data-hidden`, `data-focused`, `data-selected`
and, on an outside day, `data-month` with the month it really belongs to.
