# Avatar

A small picture that stands for a person: their image when there is one, their initials when there
is not. The avatar is display only: it has no hover, no focus and no events. A clickable avatar is
an `Avatar` inside a `Button` or a menu trigger, which owns the click and the focus.

## How to use

`name`, `size` and `color` are required. `src` is optional:

```tsx
import { Avatar } from '@signozhq/ui';

export default function Owner({ user }) {
	return <Avatar name={user.name} src={user.avatarUrl} size="md" color="primary" />;
}
```

## Sizes and shapes

`size` is `sm` or `md`. `sm` is 24px with an 11px letter, and `md` is 32px with a 13px letter. They
are the same sizes as `Skeleton.Avatar`, so a skeleton and the avatar that replaces it line up.

`shape` is `circle` by default, or `square` for a square with rounded corners. `Skeleton.Avatar`
takes the same two values.

```tsx
<Avatar name="Alex Example" size="sm" color="primary" />
<Avatar name="Alex Example" size="md" shape="square" color="primary" />
```

## Color

`color` is required. It picks the fill behind the initials and the color of the initials, and the
generic user icon takes the same pair. It is the same palette as `Badge`:

| `color`            |
| ------------------ |
| `primary`          |
| `secondary`        |
| `danger`           |
| `warning`          |
| `success`          |
| `info`             |
| `archive`          |
| `highlight-danger` |

An image covers the fill once it has loaded, so the color shows while the image loads and when it
fails.

```tsx
<Avatar name="Alex Example" size="md" color="success" />
```

## Image

With `src`, the avatar shows the image cropped to fill the shape and centred, so a portrait or a
landscape picture never stretches. The image loads lazily.

The initials show while the image loads and stay when it fails. The image replaces them only once it
has loaded, so the avatar is never an empty shape.

When `src` changes, the avatar loads the new image, even if the previous one failed. A reused avatar
in a list or a table never keeps the fallback of the row it showed before.

## Initials

The initials come from `name`, in upper case. The avatar shows at most two letters, at both sizes.

| `name`                     | Initials | Rule                                                      |
| -------------------------- | -------- | --------------------------------------------------------- |
| `Alex Example`             | `AE`     | Two or more words: first letter of the first and the last |
| `alex`                     | `A`      | One word: its first letter                                |
| `alex.example@example.com` | `A`      | An email: the part before `@`, which dots do not split    |

## Empty name

When `name` is empty or only spaces, and there is no image to show, the avatar renders a generic
user icon in place of the initials. Its accessible name is `Unknown user`.

The avatar is not hidden, so a list keeps its alignment, and the missing name stays visible.

```tsx
<Avatar name="" size="md" color="primary" />
```

## Inside a button

The avatar is not focusable and reacts to no click. To make it clickable, put it inside a `Button`,
which shows the focus ring and handles `Enter` and `Space`:

```tsx
<Button
	variant="ghost"
	color="secondary"
	size="md"
	prefix={<Avatar name={user.name} size="sm" color="primary" aria-hidden="true" />}
>
	{user.name}
</Button>
```

In an icon button, the avatar is the child and the button needs an `aria-label`:

```tsx
<Button
	variant="outlined"
	color="secondary"
	size="md"
	icon
	aria-label={`Open the profile of ${user.name}`}
>
	<Avatar name={user.name} size="sm" color="primary" aria-hidden="true" />
</Button>
```

## Accessibility

The avatar renders `role="img"` and its `aria-label` is `name`, or `Unknown user` when `name` is
blank. The image inside has an empty `alt`, and the initials and the icon are `aria-hidden`, so a
screen reader reads the name once and never spells out the letters.

When the name is printed next to the avatar, pass `aria-hidden="true"` so the screen reader does not
read the name twice:

```tsx
<>
	<Avatar name={user.email} size="sm" color="primary" aria-hidden="true" />
	<span>{user.email}</span>
</>
```

Any `aria-*` prop is forwarded to the avatar.

The avatar is not focusable and is skipped by `Tab`. No key does anything on it.

## Layout

The avatar has a fixed size from `size` and does not shrink in a flex row. The image and the initials
never leave the shape: the avatar clips its content.

The letters use the same weight and case everywhere, so an avatar in a table cell and one in a card
title look the same.

## Asserting on it

`testId` becomes `data-testid` on the avatar, and it names the image and the fallback:

| Element               | `data-testid`              |
| --------------------- | -------------------------- |
| image                 | `` `${testId}-image` ``    |
| initials or user icon | `` `${testId}-fallback` `` |

The image renders with a `src`, until it fails. The fallback renders until the image has loaded, so
the two exist together while the image loads.

The avatar mirrors `size` on `data-size`, `shape` on `data-shape` and `color` on `data-color`. With a `src` it also carries
`data-image-status`, with the value `loading`, `loaded` or `error`. Without a `src` the attribute is
absent. Use it to wait for the image or to assert the fallback.

Otherwise use the `data-slot` attributes, never the hashed class names.
