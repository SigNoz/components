# Input

A one-line text field: a native `<input>` inside a frame that owns the border, the sizes, the
validation states and the `prefix`/`suffix` slots. `Input.Password`, `Input.TextArea` and
`Input.Number` swap the control and keep the frame.

The input has no visible label of its own. The label, the description and the validation message
belong to `Field`, which wraps any one control and owns that layout, see the `Field` page.

## How to use

Every native input prop lands on the `<input>`, so react-hook-form's `register()` spreads straight
onto it. Name a bare input with `aria-label`, or put it inside a `Field`, whose label reaches it on
its own.

```tsx
import { Field, Input } from '@signozhq/ui';

export default function OrganisationField({ register, errors }) {
	return (
		<Field label="Your Organisation Name" error={errors.organisation?.message}>
			<Input placeholder="For eg. Simpsonville..." {...register('organisation')} />
		</Field>
	);
}
```

## Sizes and variants

`size` is the height of the field: `sm` is 24px, `md` is 32px, `lg` is 40px. The text does not change size.

`variant="unstyled"` drops the border and the background and keeps everything else: padding,
height, text, and the focus ring, which is the only thing marking focus there.

## Status

`status` tints the border and the background and renders a matching icon at the trailing edge,
after the `suffix`. `danger` also announces itself as `aria-invalid`. `success` is confirmation of
a completed check (name available, connection verified), not a resting state for a valid field.

Inside a `Field`, the field's `status` is the default, and the description or message of the field
lands in the input's `aria-describedby`. The input's own `status` wins when both are set.

## In a form

`InputField` is `Input` inside a `Field`, in one element, and it renders the same DOM as the
hand-written pair. It takes the props of the field and the props of the input in one object:
`label`, `labelIcon`, `labelTooltip`, `description`, `error`, `status`, `message` and `required` go
to the field, which hands `status` and `required` to the input, and every other prop goes to the
input.

```tsx
import { Button, Form, InputField } from '@signozhq/ui';

export default function EmailForm({ register, errors, onSubmit }) {
	return (
		<Form onSubmit={onSubmit}>
			<InputField
				label="Email"
				required
				type="email"
				error={errors.email?.message}
				{...register('email')}
			/>
			<Button type="submit" variant="solid" color="primary" size="md">
				Save
			</Button>
		</Form>
	);
}
```

`register()` spreads straight onto it, and `id`, `ref`, `name`, `aria-*` and `data-*` land on the
native input. `testId` is the input's, and the field parts take it as their prefix:
`${testId}-label`, `${testId}-label-tooltip`, `${testId}-description` and `${testId}-message`. The
field root gets no `data-testid`. `htmlFor` is not accepted, because the shorthand wires the id
itself.

`InputField.Password`, `InputField.TextArea` and `InputField.Number` do the same for the members.
They take the field props and the props of the member, listed under the member's own props below.
`InputField.Number` is not a target for `register()`: use a `Controller`.

The field owns the label, the description and the message, and the input owns its frame. Read the
`Field` page for the label, the message and the accessibility the pair wires, and the `Form` page
for submit and validation.

## Focus

Keyboard focus draws a 1px ring one pixel outside the field edge. A click or a tap into the field
does not, and the ring stays off while you type after a click. Focus moved by a script draws it
unless a pointer came first. The ring fades in and out with the hover and state changes. The
border itself never changes color on focus: the ring is the one focus signal, the same as every
other control. `noFocusRing` is for a surface that draws a focus treatment of its own; never use it
with `variant="unstyled"`.

## Disabled and read-only

`disabled` fades the field, blocks typing, and leaves it out of the tab order and the form submit.
Hover still opens `disabledTooltip`. `readOnly` fades it less and locks the value; the field keeps
its tab stop and its value stays selectable and copyable. `readOnly` outranks `disabled`.

Each state travels with its reason: `disabled` with `disabledTooltip`, `readOnly` with
`readOnlyTooltip`. Pass the reason as `undefined` when there is none to give.

## Members

`Input.Password` is `Input` with a visibility toggle in the suffix slot: no `type` and no `suffix`
of its own.

`Input.TextArea` is the multi-line field. It grows with its `rows`, resizes vertically by hand, and
has no `prefix`/`suffix`.

`Input.Number` holds a number, `null` while empty. `onChange` reports the parsed value, not the
event, and the field steps with the buttons at its trailing edge, the arrow keys (`Shift` for
`largeStep`) and `Home`/`End`. It is not a target for `register()`; use a react-hook-form
`Controller`.

## Asserting on it

`testId` becomes `data-testid` on the frame, and the prefix of the parts. With `testId="org"` the
input is `org-field`, the slots `org-prefix` and `org-suffix`, the status icon `org-status`, the
password toggle `org-toggle`, and the step buttons `org-step-up` and `org-step-down`.

Otherwise reach for the role and the data attributes, never the hashed class names:

| `data-slot`             | rendered                                             |
| ----------------------- | ---------------------------------------------------- |
| `input`                 | the frame                                            |
| `input-field`           | always, the native control                           |
| `input-prefix`          | while `prefix` renders something                     |
| `input-suffix`          | while `suffix` renders something                     |
| `input-status-icon`     | while `status` is set, `aria-hidden`                 |
| `input-password-toggle` | on `Input.Password`                                  |
| `input-stepper`         | on `Input.Number` with `controls`                    |
| `input-step-up`         | on `Input.Number` with `controls`, disabled at `max` |
| `input-step-down`       | on `Input.Number` with `controls`, disabled at `min` |

The frame has `data-size`, `data-variant`, `data-status` while one is set, `data-disabled` while
disabled and not read-only, `data-readonly` while read-only, `data-no-focus-ring` with
`noFocusRing`, `data-focus-visible` while the field has keyboard focus, and `data-member` (`password`, `textarea` or `number`) on the members.
