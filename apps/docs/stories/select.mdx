# Select

A field that picks one value, or several, from a short list, rendered through Base UI's `Select`.
It takes its rows as data, and looks like `Combobox` closed and like `Dropdown` once open: the same
field, rows, group headings, separators and empty row.

Use it for a list short enough to read. When the list needs a search, use `Combobox`, which takes the
same rows. For a menu of actions, use `Dropdown`.

## How to use

`items` and `placeholder` are required. There are no subcomponents to compose: the select owns its
markup.

```tsx
import { Select } from '@signozhq/ui';
import { useState } from 'react';

export default function FrameworkField() {
	const [framework, setFramework] = useState<string | undefined>();

	return (
		<Select
			aria-label="Framework"
			placeholder="Select a framework..."
			items={[
				{ type: 'item', value: 'react', label: 'React' },
				{ type: 'item', value: 'vue', label: 'Vue' },
				{ type: 'item', value: 'angular', label: 'Angular' },
			]}
			value={framework}
			onChange={setFramework}
		/>
	);
}
```

## Naming the field

The trigger is `role="combobox"`. Name it with `aria-label`, with `aria-labelledby` pointing at a
visible label, or with a `<label htmlFor>` pointing at its `id`, in single and multiple mode alike.
The list takes the same name. With none of them, the trigger falls back to the `placeholder`, which
is not a label.

```tsx
<label htmlFor="provider">Provider</label>
<Select id="provider" placeholder="Select a provider..." items={providers} />
```

## The rows

Every row carries a `type`:

| `type`      | What it is                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------- |
| `item`      | A value the user can pick. `value` is what `onChange` reports.                                  |
| `group`     | A heading and the rows under it. A group cannot hold another group.                             |
| `separator` | A rule between two runs of rows. Dropped when it would land first, last or next to another one. |

An `item` takes a `prefix` and a `suffix` around the label, and `disabled` + `disabledTooltip`. A
disabled row stays reachable with the arrow keys, so its reason shows on hover. `displayValue` is the
text the trigger and the chips show in place of the label. A single trigger also shows the selected
row's `prefix` before the value, so put an icon there rather than inside the label.

```tsx
<Select
	aria-label="Database"
	placeholder="Select a database..."
	items={[
		{ type: 'item', value: 'postgres', label: 'PostgreSQL', prefix: <Database /> },
		{
			type: 'item',
			value: 'mysql',
			label: 'MySQL',
			prefix: <Database />,
			disabled: true,
			disabledTooltip: 'Not supported yet',
		},
	]}
/>
```

A label that renders nothing shows `<No label>`.

## Values

`value` is a `string`, or a `string[]` with `multiple`. Writing `value` makes the select controlled,
even with `undefined`. Leave it out and use `defaultValue` for one that keeps its own state.

`onChange` gets a `string` in single mode and a `string[]` with `multiple`, so there is nothing to
cast. A single select has no way to clear its value once picked.

```tsx
const [frameworks, setFrameworks] = useState<string[]>([]);

<Select
	multiple
	aria-label="Frameworks"
	placeholder="Select frameworks..."
	items={frameworkItems}
	value={frameworks}
	onChange={setFrameworks}
/>;
```

A multiple select shows a chip per value. `maxDisplayedPills` folds the rest into a `+N` chip, whose
tooltip lists them. Chips that do not fit wrap, and the trigger grows to hold them.

A selected value that `items` does not have shows as itself in the trigger and in its chip.

## What the trigger shows

`displayValue` replaces what the trigger shows. A single select passes the selected row, and the
result takes the place of the row's `prefix`, `displayValue` and label. A multiple select passes the
selected rows, and the result takes the place of the chips. Both run while nothing is selected too,
with `undefined` or `[]`.

```tsx
<Select
	multiple
	aria-label="Services"
	placeholder="Select services..."
	items={serviceItems}
	displayValue={(rows) => (rows.length === 0 ? 'All services' : `${rows.length} services`)}
/>
```

## Loading and empty

`loading` puts a spinner in the trigger and replaces the rows with `loadingContent`, or a spinner
row. The popup still opens.

An empty `items` shows one row with `noContent`, `No results found :/` by default, and logs a warning
unless `noContent` is set or `loading` is true.

## Invalid

`aria-invalid` reaches the trigger like any other `aria-*` prop and turns its border red. Set it from
the form's validation, next to an error message the trigger points at with `aria-describedby`.

```tsx
<Select
	aria-label="Framework"
	placeholder="Select a framework..."
	aria-invalid={error !== undefined}
	aria-describedby="framework-error"
	items={items}
/>
```

## Keyboard

- `Enter`, `Space` and the arrow keys on the trigger open the popup and move the focus to the
  selected row, or to the first one.
- The arrow keys move the highlight and stop at the first and the last row. `Home` and `End` jump
  to them.
- Typing a letter moves to the next row that starts with it. On a closed single trigger it picks
  that row, the way a native `<select>` does.
- `Enter` and `Space` pick the highlighted row. A single select closes, a multiple one stays open.
- `Escape` closes the popup and gives the focus back to the trigger. Inside a `Dialog`, it closes
  only the popup.

## Inside a popover, dialog or drawer

Inside a `Dialog` or `Drawer` the popup goes into the panel on its own. Inside a modal or drawer from
another library, such as antd's, the popup stays in the body and stacks above it. Inside anything
else that closes on a press outside it, such as a `Popover`, pass `container` an element inside it.

```tsx
const containerRef = useRef<HTMLDivElement>(null);

<PopoverContent>
	<Select
		aria-label="Environment"
		placeholder="Select an environment..."
		items={environments}
		container={containerRef}
	/>
	<div ref={containerRef} />
</PopoverContent>;
```

## Holding the popup open in a story or a test

`ForceOpenProvider`, from `@signozhq/ui/testing`, puts the popup of every Select under it on screen
and keeps it there: clicks, keys, selections and presses outside stop driving it. Stories need it
because two popups never stay open together on their own. A disabled or read-only select stays
closed. The select has no `open` prop: in app code the user opens and closes it.

```tsx
import { ForceOpenProvider } from '@signozhq/ui/testing';

<ForceOpenProvider>
	<Select aria-label="Framework" placeholder="Select a framework..." items={frameworks} />
</ForceOpenProvider>;
```

## Asserting on it

`testId` becomes `data-testid` on the trigger, and it names everything under it:

| Element            | `data-testid`                          |
| ------------------ | -------------------------------------- |
| row                | `` `${testId}-item-${value}` ``        |
| row prefix         | `` `${rowTestId}-prefix` ``            |
| row suffix         | `` `${rowTestId}-suffix` ``            |
| group              | `` `${testId}-group-${value}` ``       |
| chip               | `` `${testId}-chip-${value}` ``        |
| chip remove button | `` `${testId}-chip-${value}-remove` `` |
| chip overflow      | `` `${testId}-chip-overflow` ``        |
| loading row        | `` `${testId}-loading` ``              |
| empty row          | `` `${testId}-empty` ``                |

`rowTestId` is the row's own `testId` or the generated one. A row or a group with its own `testId`
keeps it. The popup parts render only while it is open.

A disabled trigger is not `disabled` in the DOM: assert `aria-disabled="true"` instead of
`toBeDisabled()`.

Otherwise use the `data-slot` attributes, never the hashed class names.
