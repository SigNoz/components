# Button

A native `<button>`, rendered through Base UI's `Button`. It has color, variant and size tokens,
prefix and suffix slots, a loading state, and it forwards every `aria-*` and `data-*` attribute.

## How to use

`variant`, `color`, `size` and the children are all required: the button has no default
appearance, every call site says what it is.

```tsx
import { Button } from '@signozhq/ui';

export default function MyComponent() {
	return (
		<Button variant="solid" color="primary" size="md">
			Click Me
		</Button>
	);
}
```

## Variants

`variant` picks the visual treatment. `solid` is filled, `outlined` and `dashed` are bordered,
`ghost` is borderless, and `link` styles the button as inline text.

`solid` and `link` take every `color`. The other three only exist in the secondary treatment, so
`color="secondary"` is the only value they accept. Anything else is a type error.

```tsx
<Button variant="solid" color="primary" size="md">Solid</Button>
<Button variant="outlined" color="secondary" size="md">Outlined</Button>
<Button variant="dashed" color="secondary" size="md">Dashed</Button>
<Button variant="ghost" color="secondary" size="md">Ghost</Button>
<Button variant="link" color="primary" size="md">Link</Button>
```

## Colors

`color` swaps the palette behind `solid` and `link`: `primary`, `secondary`, `danger`, `warning`,
`success`, `info`, `archive` and `highlight-danger`.

```tsx
<Button variant="solid" color="primary" size="md">Primary</Button>
<Button variant="solid" color="danger" size="md">Danger</Button>
<Button variant="solid" color="warning" size="md">Warning</Button>
<Button variant="link" color="success" size="md">Success</Button>
```

## Sizes

`size="sm"` is 24px tall, `size="md"` is 32px. In `icon` mode both are square.

```tsx
<Button variant="solid" color="primary" size="sm">Small</Button>
<Button variant="solid" color="primary" size="md">Medium</Button>
```

## Icons

`prefix` and `suffix` place an element before or after the label. For an icon-only button, set
`icon` and pass the icon as the only child: `prefix` and `suffix` are not allowed in that mode,
and `aria-label` is required because there is no text to announce.

```tsx
import { ChevronRight, Ellipsis, Plus } from '@signozhq/icons';

<Button variant="solid" color="primary" size="md" prefix={<Plus />}>
	Create alert
</Button>
<Button variant="outlined" color="secondary" size="md" suffix={<ChevronRight />}>
	Next
</Button>
<Button variant="ghost" color="secondary" size="md" icon aria-label="More actions">
	<Ellipsis />
</Button>
```

## Loading

`loading` stops the button from responding to clicks and keyboard activation, and cross-fades a
spinner over the `prefix` slot. The label and `suffix` stay visible.

```tsx
<Button variant="solid" color="primary" size="md" loading prefix={<Plus />}>
	Saving...
</Button>
```

`loadingTooltip` is optional and says what the button is busy with, on hover or focus, for as long
as `loading` is true. The spinner alone is already a valid busy state, so reach for it when the
wait is long enough that the user deserves to know what is happening.

```tsx
<Button
	variant="solid"
	color="primary"
	size="md"
	loading={isSaving}
	loadingTooltip="Saving your changes"
	prefix={<Plus />}
>
	Save
</Button>
```

## Text overflow

`textOverflow` decides what happens to the label when it does not fit the width of the button.
`ellipsis` is the default: it truncates the label and shows the full text in a tooltip on hover or
focus, and only while the label is actually truncated, so a label that fits never opens one.
`none` clips the label at the edge of the button, with no ellipsis marker and no tooltip.

```tsx
<Button variant="solid" color="primary" size="md" width="12rem">
	Delete every alert rule in this workspace
</Button>
<Button variant="solid" color="primary" size="md" width="12rem" textOverflow="none">
	Delete every alert rule in this workspace
</Button>
```

The tooltip belongs to `ellipsis` alone, and icon buttons (`icon`) have no label, so they never
get one.

## Disabled

`disabledTooltip` is mandatory whenever `disabled` is set, and it only opens while the button is
disabled. The two travel together in both directions: a `disabledTooltip` without `disabled` is a
type error too.

```tsx
<Button
	variant="solid"
	color="primary"
	size="md"
	disabled={!canEdit}
	disabledTooltip="You need write access to edit alerts"
>
	Edit alert
</Button>
```

A native `disabled` button receives no hover or focus events, so the tooltip would be unreachable
on it, and clicking a button that goes native-disabled mid-interaction throws the focus away. The
button therefore never uses the native attribute: it carries `aria-disabled` instead, which keeps
clicks and keyboard activation blocked but leaves the button hoverable and in the tab order.

## Stacked tooltips

The button owns up to two tooltips at a time: a reason, and the full text of a truncated label.
Two tooltips anchored to the same element would open on the same hover and render on top of each
other, so both go into one popup, the reason first and the label under it, with a divider between
them.

The reason slot holds `loadingTooltip` while the button is loading, and `disabledTooltip` while it
is disabled and idle. Only one of them can ever show.

Wrapping the button in a tooltip of your own adds your title to that same popup, above both:

```tsx
<Tooltip title="Removes every rule, cannot be undone">
	<Button
		variant="solid"
		color="primary"
		size="md"
		width="12rem"
		disabled={!canEdit}
		disabledTooltip="You need write access to edit alerts"
	>
		Delete every alert rule in this workspace
	</Button>
</Tooltip>
```

```
Removes every rule, cannot be undone
────────────────────────────────────
You need write access to edit alerts
────────────────────────────────────
Delete every alert rule in this workspace
```

While `loading`, `disabledTooltip` drops out because the spinner already says the button is busy,
and `loadingTooltip` takes its place. A truncated label keeps its entry either way.
